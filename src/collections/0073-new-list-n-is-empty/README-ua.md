# #0073 - new List&lt;T&gt;(n) порожній

## 💥 Симптом

Список, який ти «розмірив» під N елементів, кидає `ArgumentOutOfRangeException` тієї ж миті, коли ти
в нього індексуєш - `list[0]` на щойно створеному `new List<int>(12)`. Або послотовий підсумок тихо
не записує нічого, бо слотів ніколи й не було. Число в конструкторі казало 12; у списку нуль
елементів.

## 🔍 Проблемний код

```csharp
var monthly = new List<decimal>(12); // 💥 12 це місткість; Count дорівнює 0 - слотів нема
monthly[month] += amount;            // ArgumentOutOfRangeException - monthly[0] не існує
```

## 🧠 Що насправді відбувається

`new List<T>(n)` бере `n` як початкову **місткість** - скільки внутрішнього сховища виділити наперед,
щоб список міг дорости до `n` без перевиділення - а не кількість елементів. `Count` усе ще `0`:
елементів нема, індексувати нічого, перебирати нічого. Місткість - це підказка продуктивності,
невидима через публічний API, окрім як через `.Capacity`; вона ніколи не створює елементів.

Хибне переконання: «`new List<int>(12)` - це як `new int[12]`». Ні. `new int[12]` - це масив
фіксованого розміру з дванадцяти нулів, який можна індексувати `[0..11]` одразу; `new List<int>(12)`
- це порожній, зростабельний список, що лише зарезервував місце під дванадцять. Двоє на вигляд
близнюки - обидва кажуть «дванадцять» - а поводяться протилежно: масив повний дефолтів, список
порожній.

## ✅ Виправлення

Якщо треба N елементів - створи N елементів: заповни список, або візьми інструмент, який справді
пре-розмірений:

```csharp
var monthly = Enumerable.Repeat(0m, 12).ToList(); // 12 справжніх елементів зі значенням 0
// або, для фіксованих індексованих слотів, природно пасує масив:
var monthly = new decimal[12];                    // 12 нулів, індексуються одразу
```

Повна версія в [Good.cs](Good.cs); помилка - у [Bad.cs](Bad.cs).

| Підхід | Коли він доречний |
|---|---|
| `Enumerable.Repeat(value, n).ToList()` | Треба `List<T>` з N елементів, наперед заповнений дефолтом - і це все ще зростабельний список, у який можна `Add`. |
| `new T[n]` (масив) | Фіксована кількість індексованих слотів, які заповнюєш за позицією (місяці, кошики, дошка) - масиви пре-розмірені й індексуються з нуля одразу. |
| `new List<T>(n)` навмисно | Ти знаєш приблизно, скільки зробиш `Add`, і хочеш уникнути перевиділення - місткість тут саме те; просто не індексуй до `Add`. |
| `new List<T>(existingCollection)` | Скопіювати наявну послідовність - цей перевантажений конструктор *заповнює* список тими елементами (Count = довжині джерела), на відміну від `int`-місткісного. |

## 😈 Ще гірший родич

Падіння - чесний результат: `[0]` кидає, і ти знаходиш одразу. Тихіша версія - код, що лише робить
`Add`: нарощування списку через `Add` працює чудово, але будь-що, що вірить у «12» -
`for (i = 0; i < 12; i++) list[i] = ...`, перевірка `list.Count`, що чекала 12, преалокація під 12
рядків - помиляється на розрив між місткістю й кількістю, і ніщо не кидає, поки індекс нарешті не
вийде за `Count`. А перевантаження поруч робить протилежне: `new List<int>(someArray)` заповнює
список із масиву (Count = його довжині), тож `new List<int>(12)` (`int`) і `new List<int>(new[]{ 12 })`
(колекція) - той самий конструктор - дають порожній список і одноелементний, залежно суто від типу
аргументу.

## 🎓 Поглиблений нюанс

- **Місткість - це підказка; список усе одно росте сам.** Перевищення місткості не кидає - список
  перевиділяє більший внутрішній масив. Число впливає лише на те, *коли* він переросте, ніколи - на
  те, що можна індексувати.
- **Два конструктори `List<T>` перевантажуються по `int` проти `IEnumerable<T>`.** `new List<int>(5)`
  обирає місткісний конструктор; `new List<int>(new[]{ 5 })` обирає конструктор-заповнювач і дає
  одноелементний список зі `5`. Та сама форма синтаксису - протилежний результат.
- **`Count` і `Capacity` - різні властивості не просто так.** `Count` - скільки елементів існує;
  `Capacity` - скільки влазить до перевиділення (`Capacity >= Count`). Читати `Capacity` як «скільки
  в списку» - та сама помилка на рівень нижче.

## 🔎 Як знайти у своїй кодовій базі

- Грепни `new List<`, за яким одразу йде індексація (`list[...]`) чи `for` по фіксованій кількості
  без жодного `Add` між ними - місткість, сприйнята за кількість.
- З боку симптомів: `ArgumentOutOfRangeException` на щойно створеному списку; послотові акумулятори
  (`totals[i] += ...`), що кидають чи нічого не пишуть; `Count`, що читається `0` одразу після
  «розмірення».
- Для фіксованих індексованих слотів бери масив (`new T[n]`) або `Enumerable.Repeat(default, n).ToList()`;
  лишай `new List<T>(n)` як підказку місткості перед серією `Add`.
- Пильнуй сусіднє перевантаження: `new List<T>(collection)` заповнює, `new List<T>(int)` резервує -
  переконайся, що написав те, що мав на увазі.
